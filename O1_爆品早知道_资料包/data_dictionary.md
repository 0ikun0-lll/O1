# O1 爆品早知道 · 数据字典

包内所有字段口径以本文为准

> **字段口径**：店铺侧 12 个字段与 `shop_hist_monthly` 均为该商品上架当日的快照；数据中不含 `group_band`。

## 0. 脱敏边界（先看这个）

| 处理 | 做法 |
|---|---|
| 身份 | item / shop / supplier / 叶子类目全部**重新编码并打乱编码顺序**（H-/S/G/C 前缀；编号大小与档位、时间均无关，编号与档位的相关系数 ≈ 0） |
| 行序 | 三张主表**行序已随机打乱**（不是按档位或时间排列，行号不携带任何信息） |
| 时间 | 真实日期整体平移为**上架批次** B01→B07；历史快照与 `demand_index` 的行标 `batch = m` 表示"**进入批次 m 之前**"的状态；`supply_count` 是 `batch = m` 的**当期供给**（业务池口径，不含标签）；店铺画像类字段一律取**商品上架当日**的店铺分区 |
| 指标 | 店铺评分→0.5 宽 band；在售 SKU 数/关注数→log2 规模带；类目需求→base-100 相对指数；**销量与 GMV 绝对值一律不下发** |
| 剔除 | 一切平台审核状态/时效/评级/操作人等字段**未进入数据包**（机审分是代理标签，禁用）；图像特征不存在 |
| 档位阈值 | 组织者持有，不随包下发；`tier` 分档仅由绝对销量阈值决定（不随批次漂移） |

### 0.1 关于 `listing_batch` —— 它不是月份

`listing_batch` 取值 `B01 … B07`，是**按真实上架时间先后切出的 7 个批次**：

- B01–B06 各覆盖**2 个自然日**的上架量，B07 覆盖 3 个（连续 15 个自然日切 7 批）；不是自然月，也不是等长周期；
- 批次之间有先后顺序（B01 最早、B07 最晚），除此之外**没有日历含义**；
- 因此**不要生成"第几月 / 季度 / 季节"类特征**——那是在拟合一个不存在的周期。

**标签成熟期**：`tier` = 上架后第 2~8 天销量分档，而批次只隔 2 个自然日，所以"上一批的标签"在预测下一批时理论上尚未成熟。本赛题由组织者**统一下架日结算标签**；参赛者只需按 `batch ≤ 当前上架批次` 取历史特征，**不需要也无法自行处理成熟期**。全部队伍同一口径，离线分数因此略有乐观偏置——这是已知设定，不是数据缺陷。

## 2. shop.csv（5,528）

`shop_id, register_batch, main_category, fulfillment_mode`

`register_batch` = 该店在本包内**首次出现**的批次。分布：B01 2,056 / B02 1,112 / B03 646 / B04 437 / B05 576 / **B06 386 / B07 315**。
`register_batch = B06` 的 386 家、`B07` 的 315 家是**训练期零历史的新店**：公开集 22.0%（660/3,000）、隐藏集 22.6%（677/3,000）的商品就来自这些"训练集里一条记录都没有"的店铺。

## 3. shop_hist_monthly.csv（38,696 = 5,528 × 7）

对"上架批次 = batch 的商品"，该店**在进入该批次之前**（严格截止，不含本批次）的历史快照；历史只由 train 窗口（B01–B05）的抽样品统计，不含测试期标签。

| 字段 | 值域 | 说明 |
|---|---|---|
| shop_id, batch | | join 键 |
| cum_sku | int | 该批次前该店商品数（73.6% 的快照里 ≤ 2，中位数 1，真实形态） |
| hit_rate_band | "无历史" 或 5% 宽区间 | 该批次前商品落在 S/A 档的占比分桶 |
| gmv_band | 0-10 | 店铺量级十分位带（0 = 无历史） |

**规则**：预测 `listing_batch = Bk` 的商品时，只取 `batch ≤ Bk` 的行。

> **终评沙箱说明**：沙箱里 `B07` 行与 `B06` 行完全相同（店铺历史只结算到训练窗口 B05；公开集 B06 的动销不进入历史表）。预测隐藏批 B07 时最多只能看到 B05 末状态，这是刻意设计，不是缺行。

## 4. category_trend.csv（8,622 = 1,437 × 6）

| 字段 | 说明 |
|---|---|
| cate_code, batch | join 键 |
| demand_index | 该类目 **`batch` 之前**已上架商品的动销指数（该类目全期均值 × 100，base-100 相对指数，无绝对量级）。**已按此口径滞后一个批次**：`batch = Bk` 的值来自 Bk-1 批次**整批结算后**的动销，**不含本批次（含被预测商品自己）的销量**；`B01` 是观测起点、没有上一批次，故为空。该值与 `tier` 一样由组织者统一结算，参赛者无需自行处理成熟期 |
| supply_count | `batch` 这一批次该类目的**供给量（业务池口径，含本批次全部商品；不是本赛题抽样后的样本数）**。量级可能远大于包内行数，且长尾类目会有极大值；只能在同一类目/同一批次的相对比较中使用（建议 log1p 或分桶），**不要与包内样本行数直接对齐**，也不要当绝对规模用 |

**规则**：`demand_index` 只取 `batch ≤ Bk` 的行；`supply_count` 是 `batch = k` 的当期供给，可作为**同批次**特征使用。

> **本包只含 B01–B06 行**（8,622）：B07 行的 `demand_index` 反映公开集（B06）当期动销，用于预测 B06 会构成时间穿越，故不下发；B07 行仅由组织者在终评沙箱中提供。

> 两列的时间窗有意不同：`demand_index` 是"过去已卖出来的需求"，`supply_count` 是"本批次的供给压力"，二者在上架当天都拿得到，但都不是标签。

## 5. cost_matrix.csv（10 种组合，6 种非零）

`true_tier, decision, cost`：驳回 S=12、A=8、B=2；放行 B=2、C=3、D=4；其余为 0。

> `cost_matrix.csv` 为本题固定评分规则，请勿修改。`baseline.py`、`evaluate.py` 都直接读取本文件（缺文件/缺行才回退内置默认值）。

决策得分（单字段地板之上的增量）：

```
决策得分 = max(0, (L_地板 - L_本方案) / (L_地板 - L_全对))
```

- **地板** = `fulfillment_mode = 全托管` 判放行、其余判驳回（真实业务规律，不是模型信号）；
- `L` = 代价表下的平均损失；锚点由**当前评分批次自己的标签档位分布**现算，所以"地板"精确锚在 **0**、"全对"精确锚在 **1**，低于地板记 **0**（不出负决策分）；
- "全对" = 逐品取放行/驳回里代价较小者。B 档两个选择代价都是 2，所以 `L_全对` 恒等于 `2 × P(B)`（≈0.59），不是 0；
- 原始决策分 `(L_全放行 - L_本方案) / (L_全放行 - L_全对)` 仍随评测输出打印，仅供对照，不计分；
- 参考值：公开 / 隐藏榜 `L_全放行 = 2.300`、`L_全对 = 0.600`、`L_全驳回 = 2.400`；B05 验证批 `2.222 / 0.592 / 2.599`；地板 L 三榜约 `1.38–1.41`。

**排序与决策口径**：

```
NDCG_adj(组) = (NDCG@100 - E[NDCG_随机]) / (1 - E[NDCG_随机])
NDCG 部分    = 0.8 × 各组 NDCG_adj 宏平均 + 0.2 × 冷启动池 NDCG_adj
客观分       = 0.6 × NDCG 部分 + 0.4 × 决策得分
```

- `E[NDCG_随机]` 按该组增益分布逐位置线性期望精确计算（组内增益全同 → 该组不参与宏平均）；
- 结果：组内全同分 ≈ **0**（同分按 `item_id` 兜底，实际在 0 附近小幅波动）、完美排序 = 1、比随机还差为负；
- 冷启动池 = `shop_id` 不在训练集里的商品（公开集 22.0% / 隐藏集 22.6%）。

## 7. 提交与复检

- **初赛（公开榜）**：截止前可多次提交 `submission_public.csv = item_id, score, decision(放行|驳回)`，每次覆盖 `test_public.csv` 全部 3,000 行，以**最后一次有效提交**为准；组织者统一回分，不设每日回分。文件必须 **UTF-8**（可带 BOM），表头大小写不敏感、忽略首尾空格。
- **终评（隐藏榜）**：截止前可更新代码包（`predict.py`），以**最后一次有效提交**为准；截止后组织者在隐藏集（3,000 行，特征不下发）上正式运行一次（计分，失败不补跑）；截止前只能在本地用验证批与公开测试集自测，组织者不提供试跑。
- **运行约束**：无网络（`network=none`）、`--data-dir` 只读、仅 CPU、≤10 分钟、内存 ≤8 GB、确定性（同输入同输出）；代码包**只可读取 `--data-dir` 与自身目录**，不得读取其它路径。标签在独立评分机上，运行容器不可见；队伍进程另由 `bwrap` / `sandbox-exec` 限制，仅挂载自身目录与数据目录，运行前会做标签可读性自检，读到任一标签即中止。
- **失败处理**：超时 / 崩溃 / 无输出 / 未通过 `validate_submission.py`（含非 UTF-8）→ 该榜客观分 **0**，不走评分器容错分支；静态扫描命中读标签 / 联网 / 越界读取 → 人工复核，确认违规则成绩作废。
- 复检项：提交格式与覆盖、时间穿越（历史/趋势批次晚于上架批次）、**编号/行序依赖**（用行号或编号大小当特征）、代码包读取范围与联网、确定性（同输入重复运行结果一致）、AI 使用声明完整性。格式/覆盖/值域/编码可脚本检查；**时间穿越与编号/行序依赖由组织者对终评代码人工抽查**。
- **缺失行处理**：本地 `evaluate.py` 默认严格校验，缺行/重复/非法值直接报错；加 `--allow-incomplete` 才按正式评分器容错：缺 score 的真值商品 → score 记 -1.0 排最后、decision 记"放行"并计入代价（**不会**用真实档位兜底）。终评 runner 会先跑 `validate_submission.py`，校验失败不进入评分。
